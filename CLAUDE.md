# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

This is the GitHub **profile README** repository (`crisMmolina/crisMmolina`). GitHub renders `README.md` on https://github.com/crisMmolina. Every visual in the README is a self-made SVG generated by Python scripts. The README pulls in no third-party widget services, except skillicons.dev for the stack row.

## Commands

```bash
python3 scripts/build_assets.py                                  # static SVGs: banner, awards, project cards, icons
GITHUB_TOKEN=$(gh auth token) python3 scripts/build_profile.py   # data SVGs: Pac-Man graph + stats (GitHub GraphQL)
```

- **Dependencies:** only the Python stdlib. The scripts must stay compatible with Python 3.9, which is the macOS system python.
- **Commit what you generate:** the README references the committed SVG files directly.

## Architecture

- **`scripts/theme.py`** holds the single palette (`THEMES["dark"|"light"]`) and the shared helpers (`chip`, `svg_doc`, reduced-motion CSS). Change colors only here. The palette is emerald green (`#022c22` / `#059669` / `#34d399`), with `#FFD700` for first places and violet (`alt`) as the contrast accent.
- **Two variants of everything:** every asset is written as `<name>-dark.svg` and `<name>-light.svg`. The README wraps each one in `<picture>` with a `prefers-color-scheme: dark` `<source>` and the light file as the `<img>` fallback. When you add an asset, follow the same pattern.
- **`build_assets.py`** turns content into SVGs. The content lives in its data lists:
  - `MEDALS`: one award per entry, newest first, written to `assets/awards/` as metro-station tiles (420×300). The README places them edge to edge, three per row (`width="33.3%"`, no whitespace between the `<a><picture>` tags), so the line segments join into one continuous "línea de logros". The first tile carries the "HOY" terminal, row ends carry chevrons, and the last tile closes the line. A train crosses each tile in its own slot of a shared cycle (`train_css`), so it reads as one train running the whole line.
  - `FEATURED`: ColonIA, drawn as the full-width card.
  - `PROJECTS`: the 2×2 grid. Each project has a motif function that draws the animated illustration on its card.
  - A project whose slug appears in `MEDALS` automatically gets its mini badges on its card (ColonIA has two: ADA and Chilangatón).
  - To update awards or projects, edit those lists and re-run the script.
- **`medals.py`** draws each station's pictogram badge, a rounded square with a metallic frame (in the spirit of CDMX Metro station icons, with original drawings), around (0,0) with a half size of 64. Callers place and scale it with a transform. Finishes: `gold` frame on emerald (1st place), `violet` (3rd place), `mint` (special mentions). Icons are original, never event or brand logos. Metal gradients use `userSpaceOnUse` because a bounding-box gradient doesn't paint on straight lines. Don't add entrance animations that start at `opacity:0`: the static frame must show every station.
- **README layout:** the Pac-Man graph and the stats city are both always visible (no `<details>`). The stack is only the skillicons row.
- **`build_profile.py`** queries the contribution calendar and repo languages, plus every year's calendar for the all-time totals and streaks, then writes to `assets/generated/`. `stats-*.svg` is an isometric city (one building per day, height scaled to contributions) on top of the minimal stats layout. Its stamp is the last day with activity, so the Action only commits when the data changes. The Pac-Man animation works like this:
  - It follows a serpentine route through the grid (SMIL `animateMotion`, paced).
  - Each cell's CSS `animation-delay` is set to the moment Pac-Man reaches it, computed from distance along the route divided by `speed`. That's what makes the eating line up with Pac-Man's position.
  - If you change the route, the cell size or the speed, compute the delays from the same distances.
- **`.github/workflows/profile.yml`** re-runs `build_profile.py` daily, on manual dispatch and on pushes to `scripts/`. It commits `assets/generated/` as `github-actions[bot]`.

## GitHub rendering constraints

- **No JS, and no `<style>` in Markdown:** CSS and animations only work inside the SVG files.
- **No external fonts or images inside SVGs** (they don't load through GitHub's Camo proxy). Use the system font stacks `SANS` / `MONO` from `theme.py`.
- **Static fallback:** each animation's base CSS state is its final state, so a frame with no animation still reads correctly. Respect `prefers-reduced-motion`.
- **Previewing:** GitHub's `<picture>` switching follows the GitHub theme, which a local preview can't reproduce. To check both variants, render with `gh api markdown` and view the light and dark files side by side.

## Content conventions

- **Language:** write prose in Spanish.
- **Source of truth:** content follows the owner's latest CV. Don't invent projects, dates or awards.
- **No public clutter:** no visit counters, trophy walls or badge walls, and don't put the phone number in the README.
- **Commits:** never add Claude/AI co-author or "generated with" lines to commits or PRs.
